## 5. Message Hierarchy

### Level 1 — Core positioning

Human-controlled operational command center for course sellers — reduce fragmentation, improve daily clarity, prepare conversations with grounded context. **Not an autonomous AI operator.**

Claim status: `IMPLEMENTATION_DEPENDENT` | `ALLOWED_WITH_DISCLOSURE` (intent/spec only until build proof).

### Level 2 — Outcome pillars

Mapped to O1–O10 per §3. All require implementation + QA proof before "available" claims.

### Level 3 — Workflow proof (WF1–WF10)

Workflow messages permitted only as **specified intent** until demo/QA/beta evidence exists.

| Allowed now | Later requirement |
| ----------- | ----------------- |
| "Phase 1 defines these operational workflows." | Demo execution + QA subset + beta journey evidence |

### Level 4 — Capability evidence (S1–S13)

Restricted by availability class (see `PHASE-1-CLAIM-CONTROL-MATRIX.md`).

### Level 5 — CTA state

See `PHASE-1-MARKETING-STRATEGY.md` §5 and `PHASE-1-MARKETING-READINESS-GATE.md`.

## 6. F001 / F002 / F003 Marketing Integrity

| Rule | Marketing constraint |
| ---- | -------------------- |
| **F001** Customer ≠ Enrollment | Never message "one customer = one enrollment" or price/limit per conflated unit |
| **F002** Attention lifecycle | Attention items are authoritative review objects; no "AI auto-fixes risk" |
| **F003** No hidden ranking | No universal AI priority score across domains; no opaque cross-queue ranking claims |
