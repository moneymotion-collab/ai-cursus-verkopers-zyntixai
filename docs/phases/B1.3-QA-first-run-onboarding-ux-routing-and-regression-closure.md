## 4. Architecture and Enforcement Review

| Concern | Finding |
| --- | --- |
| `/onboarding` | Server component; auth → `readOnboardingContext` → wizard or status panel |
| Incomplete owner landing | `resolveAuthenticatedLanding` → `buildOnboardingPath(organizationId)` |
| Completed owner landing | `buildProductDestination(organizationId)` → `/leads?org=<uuid>` |
| Product CRM gate | `enforceProductOnboarding` on lead/customer/task resolvers — **owners only** |
| Non-owner incomplete org | CRM allowed; `/onboarding` shows owner-required panel (avoids loops) |
| Middleware | Session protection only; **does not** query `onboarding_completed_at` |
| Draft / complete | Server actions → B1.2 `apply_organization_onboarding` RPC |
| Client completion trusted | **NO** — no client timestamp / completion boolean in payload |

**Server-side enforcement: YES.** Client-only redirect is not the sole control.

## 16. Defects and Conditions

### Blocking defects

None.

### Non-blocking observations (conditions)

1. **No-membership `/onboarding` CTA** — panel “Continue setup” href resolves to `/login` rather than `/register/complete`. Login landing remains `/register/complete`; no onboarding↔complete loop observed. Prefer aligning CTA to `/register/complete` in a later polish phase.
2. **Step 2 first-invalid focus** — when both offering and audience were empty, focus landed on the second invalid control once; Step 1 and Step 3 focused the first invalid field correctly.
3. **Dev cache fragility** — concurrent full `build` while `next dev` was running corrupted `.next` until restart. Operational note for local QA only.

- Confirm incomplete vs completed owner routing against the published production Auth + B1.2 schema with controlled QA identities (no production mutation beyond approved R1 scope).
