### Defect extracted from B1.1-QA

| Item | Detail |
| --- | --- |
| Implicated forms | Login, register, forgot-password, reset-password (no explicit `method`; effective native `GET`) |
| Reproduction | QA browser submit produced `/login?email=…&password=…`; DOM showed `methodProp: "get"` |

| Remediation boundary | Explicit POST on Auth forms + structural/native safety tests only |

## 3. Blocking Finding Reproduction

| Form | Before remediation |
| --- | --- |
| `LoginForm` | No `method` → native GET |
| `RegisterForm` | No `method` → native GET |
| `ForgotPasswordForm` | No `method` → native GET |
| `ResetPasswordForm` (with session) | No `method` → native GET |

**Exposure channel:** HTML form default method is GET → field names/values appear in the query string when JS `preventDefault` does not run (late hydration, JS failure, or automation race).

Sentinel used only in local tests: `B1_1_FIX_TEST_SECRET_DO_NOT_USE` (never sent to remote Auth).

## 5. Remediation

For each affected form:

| Previous | Corrected |
| --- | --- |
| `<form … onSubmit={…}>` without method | `<form method="post" … onSubmit={…}>` |

**Why credentials can no longer enter the URL:** browsers place form fields in the request **body** for POST, not the query string. JS-controlled submit still uses server actions and never puts passwords into `router.replace` destinations.
