## 6. Lifecycle-Matrix Summary

| Current status | Permitted next statuses |
| --- | --- |
| `pending` | `active`, `cancelled` |
| `active` | `paused`, `completed`, `cancelled` |
| `paused` | `active`, `completed`, `cancelled` |
| `completed` | none |
| `cancelled` | none |

Lifecycle form exposes valid next statuses only; optional reason max 500; terminal confirmation required for `completed`/`cancelled`; same-status transition is an authoritative safe no-op; archived Enrollments cannot transition.

## 7. Lifecycle Timestamp and History Summary

- `started_at` populated on first activation only
- `completed_at` populated on completion
- `cancelled_at` populated on cancellation
- Creation and lifecycle transitions create status-history entries
- Archive and restore do **not** create status-history entries

## 8. Ownership Summary

- Foreign and inactive memberships rejected
- Update payload contains only `owner_member_id`
- Customer, Program, status, source, organization, metadata, and archive state are not editable through `/edit`
- Archived Enrollments cannot be owner-updated
