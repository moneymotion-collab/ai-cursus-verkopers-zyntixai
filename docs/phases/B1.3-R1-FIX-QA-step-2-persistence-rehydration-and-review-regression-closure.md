## 4. Claimed Root-Cause Review

### What the remediation changes (verified in source)

1. `export const dynamic = "force-dynamic"` on `/onboarding`.
2. After successful draft: `setValues(result.context)` then `router.refresh()` then `setStep(+1)` (refresh not awaited).
3. Remount `key` from organizationId + persisted onboarding field snapshot.
4. `resolveInitialOnboardingStep` requires canonical enums (unknown → owning step).
5. `reviewLabels` returns `"—"` for non-canonical values.
6. `firstInvalidField` prefers `primaryOffering` before `primaryAudience`.

### Adversarial answers

| # | Question | Independent answer |
| --- | --- | --- |
| 1 | Could `/onboarding` previously be statically optimized / serve cached RSC? | **Plausible.** Pre-fix page had cookies + `searchParams` (normally dynamic) but **no** explicit `force-dynamic`, unlike `/register`. Production Full Route Cache / shared RSC payload remains the best explanation for B1.3-R1; not proven by local stale reproduction. |
| 2 | Does the page now force per-request authoritative rendering? | **YES** — source `force-dynamic` + build `ƒ /onboarding`. |
| 3 | Does draft success wait for the server write before refreshing? | **YES** — `await saveOnboardingDraftAction(...)`; refresh only on `result.ok`. |
| 4 | Does `router.refresh()` preserve route and org context? | **YES** — refresh revalidates current URL; org comes from session membership / `?org=` UUID, not rewritten by refresh. |
| 5 | Can refresh race with Step 3 transition? | **Possible in theory** (refresh not awaited). Journeys observed no wrong step/values; remount after key change re-resolves to Step 3 when Step 2 fields persist. |
| 6 | Can Step 3 render from pre-save RSC payload? | **Mitigated** — client sets values from write result before advance; hard refresh with `force-dynamic` re-reads DB. Local next-start hard refresh preserved A/B. |
| 7 | Remount only when authoritative server data changes? | **Mostly** — key is server context fields; unsaved client edits are not in the key until save+refresh updates props. |
| 8 | Can remount erase unsaved input? | **Idle remount without prop change: no.** Unsaved Step 1/2 edits survived idle waits in Journey G. Save+refresh remount is intentional. |
| 9 | Infinite refresh/navigation loop? | **NO** — `NO_REFRESH_LOOP: PASS`; single-save RSC delta ≈ 1. |
| 10 | Can tenants share cached onboarding output? | **NO evidence** — Fixture A vs E, repeated refresh, `CROSS_TENANT_CACHE_LEAK: NO`. Auth cookies scope requests. |

**Hydration/stale-RSC diagnosis:** **Supported as the best fit** for the production R1 symptom and for the code gaps closed by this fix; **not confirmed by reproducing stale values under local next start**. Persistence/read-model swap diagnoses are **rejected** by independent mapping proofs.

**Exact first stale layer (claimed):** page initial-data / RSC payload after refresh — accepted as the production hypothesis; local first incorrect layer was **not observed** (values stayed correct).
