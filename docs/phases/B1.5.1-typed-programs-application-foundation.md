| staff/viewer | None | Yes | No |

## 12. Validation Schemas

Zod create/update/transition/archive/restore + list filters/sort/pagination. Strict objects; UUID identifiers; delivery/status enums; trimmed name; no `expected_end_date`; unsupported fields rejected.

---

## 13. Adapter Architecture

`PROGRAM_RPC_NAMES` → `create_program`, `update_program`, `transition_program_status`, `archive_program`, `restore_program`.  
Each call resolves membership via `resolveOrganizationContext` before RPC. Browser org id never authorizes alone. Transition source forced to `manual`. Metadata defaults to `{}`.

---

## 14. Loader Architecture

- `listPrograms` / `getProgramById` / `listProgramStatusHistory` / `countOpenEnrollmentsForProgram`
- `loadProgramsListFoundation` / `loadProgramDetailFoundation`
- Open enrollment count uses proven open definition: status ∈ `pending|active|paused` and `archived_at is null`
- RLS SELECT via authenticated server client

---

## 15. Action Architecture

Server actions: create/update/transition/archive/restore. Validate → membership → verified role → mutation → revalidate `/programs` (+ detail when known). No UI forms in this phase.

---

## 16. Error Mapping

Stable codes including `ARCHIVE_BLOCKED_OPEN_ENROLLMENTS`, `DUPLICATE_PROGRAM`, `TRANSITION_NOT_ALLOWED`, `INVALID_DELIVERY_MODE`, `PROGRAM_UNAVAILABLE`, auth/org/permission/network/server families. User messages safe; raw SQL not exposed.

---

## 17. Authenticated Membership Handling

`resolveOrganizationContext` + `resolveProgramPageOrganization` (onboarding gate reused). Mutations require known Program role from membership context.

---

## 18. Tenant-Isolation Guarantees

Org-scoped queries and RPC `p_organization_id` from resolved membership. Fail closed when membership missing. No service-role client. No direct unsafe `programs` writes — mutations via SECURITY DEFINER RPCs only.
