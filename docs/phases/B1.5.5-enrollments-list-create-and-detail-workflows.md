## 6. Customer Eligibility

Loaded only when:

- same authenticated organization;
- `archived_at` is null;
- status is `onboarding` or `active`.

Ineligible, archived, and foreign-tenant customers are excluded by the authenticated query filters. Final eligibility remains RPC-authoritative.

---

## 7. Program Eligibility

Loaded only when:

- same authenticated organization;
- `archived_at` is null;
- status is exactly `active`.

Inactive, archived, and foreign-tenant programs are excluded. Final eligibility remains RPC-authoritative.

Unknown/absent roles fail closed. Loader and action paths re-check capabilities independently of UI visibility.

## 9. List Workflow

Route: `/enrollments`

- Organization from authenticated membership via `resolveEnrollmentPageOrganization`
- URL allowlisted state: `org`, `q`, `status`, `archived` (role-gated), `sort`, `direction`, `page`, `pageSize`
- Search against Customer display name / Program name (foundation)
- Sort: `enrolled_at` (default) \| `updated_at` \| `status` \| `created_at`
- Pagination defaults 25 / max 100
- Rows: Customer, Program, Status, Owner (label map), Enrolled date, archived badge
- Distinct empty / no-results / archived-empty / recoverable error states
- Role-aware New Enrollment CTA

---

## 10. Create Workflow

Route: `/enrollments/new`

- Loader denies Viewer (`action_unavailable`)
- Loads eligible customers, active programs, and active members (cap 100)
- Clear empty-option messaging; submit disabled when customers or programs are empty
- Client form → `createEnrollmentAction` → `create_enrollment` RPC
- Duplicate-open / eligibility / unavailable errors mapped to safe UI messages
- Success redirects to new Enrollment detail; list/detail paths revalidated by published action
- No org/role selectors; no source/metadata fields; no direct insert

---

## 11. Detail Workflow

Route: `/enrollments/[enrollmentId]`

Read-only presentation:

- Status and archive state
- Related Customer and Program (org-scoped links when available)
- Owner label, source label
- Enrolled / started / completed / cancelled / created / updated / archived timestamps
- Status history section
- Back navigation preserving list query state

Explicitly absent: status transition, edit, owner/metadata update, archive, restore, Progress, AI/attention.

---

## 12. History Presentation

- Uses foundation `listEnrollmentStatusHistory` (deterministic ordering, capped)
- Transition labels, source labels, timestamps
- Actor labels resolved when member IDs are available
- States: ready / empty / error (recoverable reload) / hidden (capability)
- No Progress data mixed into lifecycle history
- No archive/restore history claims beyond what status-history rows record

---

## 13. Archived Visibility

- Owner/Admin: archived filter available; archived rows/detail visible when authorized
- Staff/Viewer: archived filter ignored/denied; list/detail foundation fails closed for archived records
- Invalid `archived=true` for unauthorized roles produces filter warning and does not expose archived rows

---

## 14. Tenant-Isolation Controls

- Org and role derived server-side from membership
- Browser org IDs never grant access alone
- Eligible option queries always filter by organization_id
- Missing / foreign / malformed Enrollment IDs collapse to the same safe unavailable shape
- No service-role or Admin client usage

---

## 15. Error Handling

- Form field errors via Zod + mutation interpretation
- Safe messages for duplicate-open, eligibility, unavailable customer/program, invalid owner
- Unknown transport/server errors use generic retryable fallback
- List/detail query errors show recoverable panels without SQL/RLS/constraint leakage
