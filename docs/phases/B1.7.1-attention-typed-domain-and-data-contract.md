## 11. Status contract

Exact values: `open` | `acknowledged` | `resolved` | `dismissed` | `expired`.

| Guard | Behavior |
| --- | --- |
| `isAttentionItemStatus` | Accepts only the five values |
| `isTerminalAttentionStatus` | `resolved`, `dismissed`, `expired` |
| `isNonTerminalAttentionStatus` | `open`, `acknowledged` |

Hard exclusions: no `snoozed`, `reopened`, `closed`, or `archived` as status. Archive remains orthogonal via `archivedAt`.

---

## 12. Transition matrix

Encoded in `status.ts` / evaluated in `transitions.ts`:

| From | Allowed to |
| --- | --- |
| `open` | `acknowledged`, `resolved`, `dismissed`, `expired` |
| `acknowledged` | `resolved`, `dismissed`, `expired` |
| terminal | _(none)_ |

Semantics:

- Same-status → `noop` (idempotent; not listed as allowed transition)
- Terminal → any → `denied` (`TERMINAL_ITEM`)
- Forbidden edges → `denied` (`INVALID_TRANSITION`)
- No role authorization or database knowledge in helpers

Helpers: `evaluateAttentionStatusTransition`, `canTransitionAttentionStatus`, `assertAttentionStatusTransition`.

---

## 13. Severity contract

Values: `low` | `medium` | `high` | `critical`.

| Item | Value |
| --- | --- |
| Default (manual) | `medium` |
| Ranks | 1–4 (low→critical) |
| Labels | Low / Medium / High / Critical |
| Excluded | numeric severity SoT, `info`, priority field, auto-escalation |

## 16. Attention Signal types

`AttentionSignal` (persisted-shaped, immutable conceptual model):

- identity: `id`, `organizationId`, `attentionItemId`, `enrollmentId`
- classification: `signalOrigin`, optional `ruleKey`
- content: `explanation`, `evidence`
- audit: `detectedAt`, `createdByMemberId`, `createdAt`

Evidence kinds: `manual_note` | `stale_progress` | `generic`.

Hard rules in B1.7.1:

- No `UpdateAttentionSignalInput`
- No status/assignment/archive on Signal
- Repeated detection is append-oriented (new Signal / detection metadata on Item later)

Column names are conceptual; B1.7.2 owns physical schema approval.

---

## 17. Attention Item types

`AttentionItem` (persisted-shaped operational model):

- identity + org + enrollment + customer/program context IDs
- `title`, `summary`, `status`, `severity`
- single `assigneeMemberId` or `null`
- `dedupeKey`, `detectionCount`, `firstDetectedAt`, `lastDetectedAt`
- lifecycle timestamps + reasons (`acknowledgedAt`, `resolvedAt`/`resolutionReason`, `dismissedAt`/`dismissalReason`, `expiredAt`)
- orthogonal `archivedAt`
- actor/timestamps: `createdByMemberId`, `updatedByMemberId`, `createdAt`, `updatedAt`

Lifecycle-dependent reason fields are validated on inputs rather than forced into an unworkable discriminated-union complexity for R1.

---

## 18. Input contracts

Typed (not RPC) inputs:

| Input | Purpose |
| --- | --- |
| `CreateManualAttentionItemInput` | Manual create |
| `RecordRuleAttentionSignalInput` | Rule detection recording |
| `AcknowledgeAttentionItemInput` | Acknowledge |
| `AssignAttentionItemInput` | Assign / unassign |
| `ResolveAttentionItemInput` | Resolve with reason |
| `DismissAttentionItemInput` | Dismiss with reason |
| `ExpireAttentionItemInput` | Expire with server timestamp |
| `ArchiveAttentionItemInput` | Archive terminal item |
| `ReevaluateAttentionRulesInput` | Org-scoped re-evaluation request shape |

Client org/actor IDs are not treated as free authorization authority. Role checks belong in later layers.

---

## 19. Validation contract

Pure validators in `validation.ts`:

- status, severity, signal origin, rule key, source type
- enrollment / item / assignee UUID shape
- manual title (required, max 200 — Tasks-aligned), explanation, optional summary
- dismissal reason required (non-empty)
- resolution reason required (non-empty)
- evidence payload shape (kind + cited Progress UUID checks)
- empty assignee string rejected; `null` = unassigned

No HTTP codes; no DB error text.

---

## 20. Dedupe key contract

Canonical builder:

```text
attention:enrollment:<organizationId>:<enrollmentId>:<signalKey>
```

where `signalKey` is `manual` or a Release 1 rule key.

Properties:

- stable / reproducible
- no PII, title, summary, or timestamps in identity
- no hash required

Helpers: `buildAttentionDedupeKey`, `buildRuleAttentionDedupeKey`, `buildManualAttentionDedupeKey`, `isNonTerminalDedupeConflict`.

---

## 21. Non-terminal uniqueness invariant

**Domain invariant:** at most one non-terminal Attention Item per dedupe key.

| Layer | Responsibility |
| --- | --- |
| B1.7.1 | Pure key + conflict helper + documentation |
| B1.7.2+ | Partial unique DB constraint on non-terminal rows |
| B1.7.3+ | Transactional RPC upsert / conflict handling |

TypeScript alone does not enforce concurrency. Terminal (including archived terminal) Items do not block a later new Item for a new incident.

---

## 22. Stale-progress rule contract

| Field | Locked value |
| --- | --- |
| Rule key | `enrollment_no_recent_progress` |
| Threshold | `14` |
| Unit | `calendar_days` |
| Timezone basis | `UTC` |
| Fallback | `enrollment_created_at` |
| Reference | max non-voided Progress `occurred_at`, else enrollment `created_at` |
| Boundary | `ageCalendarDays >= 14` → stale |
| Proposed severity | **Not** emitted (B1.7.0 did not lock a proposed severity from this rule) |

Pure evaluator: `evaluateEnrollmentNoRecentProgress` with injected `evaluatedAt` (no hidden `new Date()`).

---

## 23. Enrollment eligibility

Eligible for this rule (B1.7.0 locked):

- status in `{ active, paused }`
- not archived (`enrollmentArchivedAt == null`)

Ineligible: `pending`, `completed`, `cancelled`, archived, and any other status.

---

## 24. Assignment contract

- At most one assignee (`assigneeMemberId: string | null`)
- Unassigned allowed (`null`)
- Empty string rejected by validation
- Active same-organization membership validation deferred to B1.7.3 server layer
- No multi-assignee, teams, or queues

---

## 25. Archive contract

- Orthogonal `archivedAt: string | null`
- Domain archive only when terminal and not already archived
- Helpers: `canArchiveAttentionItem`, `assertCanArchiveAttentionItem`, `isArchivedAttentionItem`, `canMutateAttentionItemOperationally`
- No role check in pure helpers
- Restore out of Release 1

---

## 26. Error contract

Stable domain codes (`AttentionDomainErrorCode`), including:

`INVALID_STATUS`, `INVALID_SEVERITY`, `INVALID_TRANSITION`, `TERMINAL_ITEM`, `ARCHIVED_ITEM`, `DISMISSAL_REASON_REQUIRED`, `RESOLUTION_REASON_REQUIRED`, `INVALID_SIGNAL_ORIGIN`, `INVALID_RULE_KEY`, `INVALID_EVIDENCE`, `INVALID_STALE_PROGRESS_INPUT`, `NON_TERMINAL_NOT_ARCHIVABLE`, plus ID/title/summary/assignee/source variants.

No HTTP status codes in the pure domain.
