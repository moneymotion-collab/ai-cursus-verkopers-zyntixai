## 5. Password-Recovery Flow

```text
/forgot-password
  → requestPasswordResetAction
  → resetPasswordForEmail(email, redirectTo = {origin}/auth/callback?next=/reset-password)
  → generic success (enumeration-safe)

Email link
  → /auth/callback?code=…&next=/reset-password
  → exchangeCodeForSession
  → /reset-password  (no owner provisioning)

/reset-password (valid recovery session)
  → updatePasswordAction
  → updateUser({ password })
  → signOut
  → /login?reset=success

/reset-password (no session) or expired callback
  → actionable expired state
  → /forgot-password?reason=recovery_expired or links to request/login
```

| Concern | Behavior |
| --- | --- |
| Request route | `/forgot-password` |
| Callback route | `/auth/callback` |
| Reset route | `/reset-password` |
| Generic response | “If an account exists for this email address, you will receive a password reset link shortly.” |
| Expired-link behavior | Forgot-password notice / reset expired panel; never raw provider errors |
| Post-success destination | `/login?reset=success` after sign-out (fresh login required) |

Registration flag does **not** gate any recovery action or route.

## 6. Routing Contract

| Route | Unauthenticated | Authenticated |
| --- | --- | --- |
| `/` | `/login` | membership landing (`/leads?org=` or `/leads`) or provisioning recovery |
| `/login` | form (+ forgot link; register CTA only if flag enabled) | redirect via post-login destination |
| `/register` | form if flag `true`; else `/login?registration=disabled` | redirected away from form |
| `/auth/callback` | code exchange; recovery → `/reset-password`; signup → provision/land | same |
| `/forgot-password` | request form | allowed (not blocked by flag) |
| `/reset-password` | expired panel without session; form with recovery session | update then sign-out to login |
| `/leads` `/customers` `/tasks` | `/login?next=…` | product workspaces (unverified email → check-email) |

Onboarding enforcement: **not implemented** (deferred to B1.2/B1.3).

## 7. Safe Redirect Contract

Authoritative utility: `resolveSafeReturnPath` in `src/features/auth/server/safe-return-path.ts`.

**Accepted:** internal paths beginning with `/` that match allowlisted families (`/`, `/leads*`, `/customers*`, `/tasks*`, exact registration recovery paths, `/forgot-password`, `/reset-password`), including safe query strings.

**Rejected:** `//…`, absolute URLs, schemes (`javascript:`, `data:`, `https:`), control characters, empty/whitespace, malformed encoding, non-allowlisted paths.

Used by login, callback, protected-route `next` preservation, and recovery callback destinations.

## 8. Registration-Flag Contract

`parsePublicRegistrationEnabled` accepts only trimmed case-insensitive exact `true`.

| Value | Enabled |
| --- | --- |
| `true` / `TRUE` / ` true ` | yes |
| `1`, `yes`, `on`, empty, undefined, whitespace, other | no |

Controls only:

- registration CTA visibility;
- `/register` availability;
- `registerAction` submission.

Does **not** disable login, logout, password recovery, password update, or callback handling.
