## 4. Route Contract

| State | `/onboarding` behavior |
| --- | --- |
| Unauthenticated | `/login?next=/onboarding` (org query preserved when present) |
| Owner, incomplete | Editable three-step wizard |
| Owner, complete | Redirect `/leads?org=` |
| Non-owner, incomplete | Owner-required status panel (no editable form) |
| No membership | Membership-required panel → `/register/complete` |
| Ambiguous memberships | Ambiguous panel → `/leads` for organization selection |
| Missing / unauthorized org | Organization unavailable panel |

---

## 5. Onboarding Enforcement

| Surface | Behavior |
| --- | --- |
| `resolveAuthenticatedLanding` | Single incomplete **owner** → `/onboarding?org=`; complete → `/leads?org=`; multi → `/leads` |
| `resolvePostLoginDestination` | Incomplete owner product `next` rewritten to onboarding; `/onboarding` allowed |
| `tryProvisionAndLand` | New org → `/onboarding?org=` |
| Leads / Customers / Tasks org resolvers | Owner of incomplete org → `redirect` to onboarding |
| Non-owner product access | Allowed (no redirect loop); `/onboarding` shows owner-required |
| Middleware | Session protection for `/onboarding`; **no** onboarding_completed_at query |
| Recovery / callback / login / register | Unaffected |

## 6. Three-Step UX

| Step | Fields | Title |
| --- | --- | --- |
| 1 | Display name, company name, business type | Tell us about your business |
| 2 | Primary offering, primary audience | What do you offer, and who is it for? |

Labels come from B1.2 `*_LABELS`. Machine values are select `value`s only. Progress: Step N of 3.

---

## 7. Draft-Save Flow

```text
Validate current step → saveOnboardingDraftAction → advance
```

- Unknown keys rejected by Zod
- Completion timestamp never set by draft
- Failure keeps the user on the step with values preserved
- Duplicate submits blocked via pending ref
- Refresh resumes from server values (`resolveInitialOnboardingStep`)

---

## 8. Completion Flow

```text
Validate step 3 → completeOnboardingAction → redirect /leads?org=
```

- Server generates / preserves `onboarding_completed_at`
- No client timestamp field
- Redirect only after `ok: true`
- Atomic profile + organization update via existing RPC

---

## 9. Existing and Completed Organizations

- Prefills profile display name and organization name
- Resumes at first incomplete step from server draft
- Completed owners never re-enter the wizard
- Direct `/onboarding` after completion → `/leads?org=`

## 17. Risks and Conditions

### Blocking

None.

### Non-blocking

1. Repository has no Playwright; browser journeys are covered by contract/UI/routing tests rather than live browser automation.
2. Non-owners of incomplete orgs retain CRM access by design to avoid redirect loops; they cannot complete onboarding.
3. Multi-org incomplete owners without `?org=` land on `/leads` for selection, then are gated when an incomplete owned org is selected.

### Production-only

Controlled production verification of the UI against the live B1.2 schema remains for later R1 after independent QA.
