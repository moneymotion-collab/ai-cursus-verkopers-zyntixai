## 6. Exact Lifecycle Transition Matrix

Mirrors `private.is_allowed_program_status_transition`:

| From | Allowed next |
| --- | --- |
| `draft` | `active`, `retired` |
| `active` | `paused`, `retired` |
| `paused` | `active`, `retired` |
| `retired` | `active` |

Same-status transitions are rejected (not idempotent success). Archived programs cannot transition.

## 8. Edit Workflow

- Route: `/programs/[programId]/edit`
- Loader: `loadProgramEditPage` — invalid ID, unavailable, archived and role denials fail closed
- Form: seeds current name / delivery mode / description; pending lock + `pendingRef`
- Action: `updateProgramAction` → `update_program`
- Success: revalidate list/detail and redirect to detail

## 9. Lifecycle Workflow

- Route: `/programs/[programId]/status`
- Loader: `loadProgramStatusPage` — only permitted targets from domain matrix
- UI: radio targets only (no free-form status dropdown)
- Action: `transitionProgramStatusAction` → `transition_program_status` (`p_source: "manual"`)
- Success: detail + history refresh hints

## 10. Archive Workflow

- Route: `/programs/[programId]/archive`
- Confirmation copy: soft-archive, not deletion; status unchanged
- Warns when open enrollment count > 0; RPC remains authoritative blocker
- Action: `archiveProgramAction` → `archive_program`

## 11. Restore Workflow

- Route: `/programs/[programId]/restore`
- Available only when archived and Owner/Admin
- Action: `restoreProgramAction` → `restore_program`
- Status preserved; visibility returns per role rules

## 12. Detail Integration

`/programs/[programId]` now wires `workflowLinks` for Owner/Admin:

- Edit / Change status / Archive when non-archived
- Restore when archived
- Staff/Viewer remain read-only (no links)
- Status + Archived badges remain prominent
- Open enrollment count and history unchanged
- No Enrollment or Progress controls

## 13. List Integration

Existing `/programs` list/create behavior preserved:

- Updated name/delivery/status appear after mutations via `revalidatePath`
- Archived filter remains Owner/Admin-only
- Create CTA remains role-aware
- No Staff/Viewer mutation controls on list

## 14. Tenant-Isolation Controls

- Organization always from authenticated membership via `resolveOrganizationContext`
- Browser-supplied organization IDs validated as UUID then membership-checked
- Role never trusted from browser input
- Foreign / invalid Program IDs map to unavailable (no cross-tenant enumeration)
- No service-role client; no direct `programs` table writes from app mutations

| Condition | Code / UX |
| --- | --- |
