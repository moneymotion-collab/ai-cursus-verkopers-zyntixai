## 5. Exact Lifecycle Matrix

Mirrors `private.is_allowed_enrollment_status_transition`:

| Current status | Permitted next statuses |
| --- | --- |
| `pending` | `active`, `cancelled` |
| `active` | `paused`, `completed`, `cancelled` |
| `paused` | `active`, `completed`, `cancelled` |
| `completed` | none |
| `cancelled` | none |

Same-status transitions are rejected (not idempotent success). Archived enrollments cannot transition.

## 6. Transition-Reason Behavior

- Optional in RPC and UI (`reason` ≤500 characters; blank → null).
- Stored on `enrollment_status_history.reason`.
- Not required for any transition.
- Source fixed to RPC default / adapter `manual` path — no UI source picker.

## 7. Lifecycle Timestamp and History Behavior

| Event | Timestamp / history effect |
| --- | --- |
| → `active` (first) | Sets `started_at` if null |
| → `completed` | Sets `completed_at` |
| → `cancelled` | Sets `cancelled_at` |
| Transition | Inserts history row (from→to, actor, reason, source) |
| Archive / restore | **No** history rows; status unchanged |

Detail history panel refreshes after successful transitions via revalidation + `refreshHints.history`.

## 8. Owner Assignment Rules

- Roles: Owner/Admin/Staff allowed; Viewer denied.
- Organization derived server-side from authenticated membership.
- Eligible options: active memberships in the same organization only (`loadEligibleEnrollmentMembers`).
- Clear/unassigned: permitted (`ownerMemberId: null`).
- Foreign / inactive membership IDs rejected by DB trigger → safe `INVALID_OWNER` mapping.
- Update payload from UI contains **only** `organizationId`, `enrollmentId`, `ownerMemberId` — never `metadata`.
- Archived enrollments: presentation, loader, mutation, and RLS all deny.

## 11. Archive Preconditions

1. Role is Owner or Admin.
2. Enrollment is not already archived.
3. Status is terminal (`completed` or `cancelled`).
4. Explicit confirmation page (archive wording, not delete).
5. Server uses `archive_enrollment` only — no direct `archived_at` write.

Non-terminal archive control is absent from detail and denied by loader + RPC.

## 12. Restore Semantics

1. Role is Owner or Admin.
2. Enrollment is archived (and still terminal per DB).
3. Clears `archived_at` only.
4. Lifecycle status, owner, and metadata unchanged.
5. Visibility returns to normal role rules.
6. Applicable non-terminal controls return only when preserved status permits them (terminal enrollments remain without transition controls after restore).

## 14. Lifecycle Workflow

- Route: `/enrollments/[enrollmentId]/status`
- Loader: `loadEnrollmentStatusPage` — only permitted targets; archived/viewer/empty transitions fail closed
- UI: radio targets only (no free-form status dropdown); optional reason; **explicit confirmation checkbox for terminal targets** (`completed` / `cancelled`)
- Action: `transitionEnrollmentStatusAction` → `transition_enrollment_status`
- Pending lock via `pendingRef`; success revalidates list/detail and redirects to detail

## 15. Ownership Workflow

- Route: `/enrollments/[enrollmentId]/edit`
- Loader: `loadEnrollmentEditPage` — eligible members; archived/viewer denials
- Form: current owner + Unassigned + active same-org members
- Action: `updateEnrollmentOwnerMetadataAction` with owner only
- No role/organization selector; no metadata field

## 17. Archive Workflow

- Route: `/enrollments/[enrollmentId]/archive`
- Shown only for non-archived terminal enrollments to Owner/Admin
- Confirmation copy: soft-archive, not deletion; status unchanged
- Action: `archiveEnrollmentAction` → `archive_enrollment`
- Cancel link performs no mutation

## 18. Restore Workflow

- Route: `/enrollments/[enrollmentId]/restore`
- Shown only when archived to Owner/Admin
- Action: `restoreEnrollmentAction` → `restore_enrollment`
- Status/owner/metadata preserved
