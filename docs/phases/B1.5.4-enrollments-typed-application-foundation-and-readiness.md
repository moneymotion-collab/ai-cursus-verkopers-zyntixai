## 4. Authoritative Schema Findings

Evidence sources (not contract assumptions alone):

- `supabase/migrations/20260705180002_create_enrollments.sql`
- `supabase/migrations/20260705180003_create_enrollment_status_history.sql`

- `src/types/database.generated.ts`
- Existing `listCustomerEnrollmentSummaries` customer summary loader

**Proven:**

1. Tables: `public.enrollments`, `public.enrollment_status_history`
2. Soft-archive via `archived_at` (orthogonal to lifecycle status)
3. Open-participation uniqueness: partial unique index on `(organization_id, customer_id, program_id)` where status ∈ `pending|active|paused` and `archived_at is null`
4. Composite unique `(organization_id, id)`
5. FKs: customer/program/owner/created_by are org-scoped composites; customer/program `ON DELETE RESTRICT`; history enrollment FK `ON DELETE CASCADE`
6. Direct authenticated INSERT/DELETE revoked; SELECT granted; UPDATE granted only for `(owner_member_id, metadata)`
7. RLS: admin SELECT includes archived; member SELECT non-archived only; staff UPDATE policy for non-archived owner/metadata
8. No `update_enrollment` RPC exists in migrations or generated types

No contract/database mismatch was found.

## 6. Exact Lifecycle Statuses

```text
pending | active | paused | completed | cancelled
```

Initial create statuses (RPC): `pending` (default) or `active`.

Sources (CHECK): `manual | lead_conversion | import | integration | system`
Public create RPC accepts only `manual`.

Open enrollment definition: status ∈ `pending|active|paused` **and** `archived_at is null`.
Terminal statuses: `completed`, `cancelled`.

| From | To |
| --- | --- |

## 12. Customer Relationship Rules

Proven by `create_enrollment`:

- Customer must exist in the authenticated organization
- Customer must not be archived
- Customer status must be `onboarding` or `active`
- Customer ID cannot escape tenant scope (org-scoped FK + RPC membership)

---

## 13. Program Relationship Rules

Proven by `create_enrollment`:

- Program must exist in the authenticated organization
- Program must not be archived
- Program status must be `active`
- Duplicate open enrollment for same customer+program raises unique-violation mapped error

---

## 14. Archive and Restore Semantics

- Archive: owner/admin; only `completed` or `cancelled`; sets `archived_at`
- Restore: owner/admin; only archived terminal rows; clears `archived_at`; does **not** reactivate to non-terminal status
- Repeated archive/restore of wrong state fails with proven exception messages

---

## 15. History Behavior

- Create writes `null → initial_status`
- Every transition writes `from → to` with optional reason and source
- Append-only `enrollment_status_history`; membership SELECT RLS
- Foundation loader caps history entries (`MAX_ENROLLMENT_HISTORY_ENTRIES = 100`)

---

## 16. Tenant-Isolation Controls

- Organization and role derive from authenticated membership via `resolveOrganizationContext` / page org resolver
- Browser-submitted organization IDs are validated as UUIDs then membership-checked; RPC adapters always pass membership-resolved `organizationId`
- Reads filter by `organization_id`; unavailable/foreign rows collapse to safe unavailable errors
- No service-role client in Enrollments foundation
