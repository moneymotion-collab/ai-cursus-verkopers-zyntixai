## 3. Official title and user goal

**Title:** B1.6.2 — Progress List and Detail Workflows

**User goal (testable):** An authenticated organization member can open the Progress workspace, browse organization-scoped progress facts (default active/non-voided), open fact detail with enrollment/customer/program context, and see role-correct read visibility (including owner/admin voided toggle). **Primary user:** Organization Owner / Admin / Staff (read + later mutate) and Viewer (read non-voided).

## 5. Scope contract

### In-scope

1. Routes: `/progress`, `/progress/[factId]` (read).  
2. List UI: filters (fact type, enrollment, customer, program; voided toggle owner/admin; default active-only), sort `occurred_at` desc, pagination, empty/no-results/loading/error.  
3. Detail UI: fact fields, void/correction lineage links (read-only), recorder label (safe fallback), enrollment/customer/program links, role-aware **hidden or disabled** mutate CTAs (no working mutation forms).  
4. Page loaders wiring foundations → UI.  
5. Enable Progress nav visibility.  
6. Automated list/detail/role/tenant/not-found/UI tests.  
7. Browser journeys for list/detail (Gate 7).  
8. Production verification of Progress list/detail after controlled deploy (Gate 8 — user-visible).  
9. Phase docs under `docs/phases/` + B1-GATE.1 dashboard at closure.

### Out-of-scope

- `/progress/new`, void, correct **working** workflows (B1.6.3)  
- PE deferral-copy remediation / contextual CTAs (B1.6.4)  
- UX polish beyond required empty/no-results (remainder → B1.6.5 / polish)  
- AI, NBA, health scores, Attention, notifications, certificates, billing, member portal  
- Schema/RLS/RPC changes; generated types; package upgrades  
- Canonical enrollment % / health rollups  
- Reopening B1-STAB.1 / Customers/Leads label helpers
