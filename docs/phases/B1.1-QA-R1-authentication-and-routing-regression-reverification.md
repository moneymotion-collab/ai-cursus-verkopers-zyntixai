## 12. Recovery-Session Authorization Observation

**Independent classification: non-blocking for B1.1 controlled production verification.**

Reasoning: `/reset-password` with any authenticated session allows the **current** user to change **their own** password via `updateUser`, then signs out. That is equivalent to a same-account password-change surface, not cross-tenant abuse. The recovery email path still lands here after callback. Recovery-AMR exclusivity would be a later hardening improvement, not a blocker for beta entry verification of POST-safe Auth.

---

## 13. Site-Origin Validation Observation

**Independent classification: non-blocking observation (production configuration condition).**

`resolveSiteOrigin` trims and prefers `NEXT_PUBLIC_SITE_URL`, then `VERCEL_URL`, else localhost. It does **not** use a formal URL schema library. Values are **operator-controlled env**, not end-user input. Misconfiguration can break email redirects; it is not an open redirect from user-controlled form fields. B1.1-R1 must confirm production `NEXT_PUBLIC_SITE_URL` is a correct https origin with Auth allowlist alignment.
