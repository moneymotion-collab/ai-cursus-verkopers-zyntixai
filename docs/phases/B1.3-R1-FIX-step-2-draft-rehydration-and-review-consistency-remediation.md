## 6. Root Cause

**First incorrect layer (production refresh path):** Page/RSC rehydration — the onboarding page’s initial-data property could be served from a **non-dynamic / Full Route Cache** render after a successful Step 2 draft, so a hard refresh revived a stale RSC snapshot instead of the just-persisted draft.

Not the first incorrect layer:

- Database mapping / enum persistence
- RPC argument swap
- Review label lookup alone (secondary hardening only)

---

## 7. Remediation

Smallest safe app-layer fix (no DB/RPC/canonical-value changes):

1. `export const dynamic = "force-dynamic"` on `src/app/onboarding/page.tsx` — always read live draft.
2. `router.refresh()` after successful draft save in `OnboardingWizard` — align App Router RSC payload with persisted draft.
3. Wizard remount `key` from authoritative context fields — remount when server context changes.
4. `resolveInitialOnboardingStep` uses canonical enum checks — unknown values recover on the owning step.
5. `reviewLabels` safe unknown → `"—"` — no false labels for non-canonical values.
6. `firstInvalidField` order: offering before audience — matches visible Step 2 order.
7. Regression tests A–H in `tests/onboarding/onboarding-step2-value-preservation.test.tsx` (+ `firstInvalidField` assertion in `onboarding-steps.test.ts`).
