## 7. Empty / no-results / unavailable / not-found contract

| Kind | When | Current pattern | B1.6.5 rule |
| --- | --- | --- | --- |
| **EMPTY** | Access ok; no org Progress facts | “No progress records yet” | Keep distinct; polish wording allowed |
| **NO RESULTS** | Filters/context yield zero | “No progress records match…” + clear filters | Keep distinct; do not invite create if role/status forbid |
| **VOIDED EMPTY** | includeVoided with none | “No voided progress records…” | Keep owner/admin-only path |
| **UNAVAILABLE** | Related fact not safely visible | “Progress unavailable…” | Must not become normal empty |
| **NOT FOUND** | Unknown / unauthorized ID | Same unavailable copy (no existence leak) | Preserve |
| **PERMISSION DENIED** | Role cannot open mutation | “Record/Void/Correct progress unavailable” + safe message | Prefer explicit deny on known role-gated routes; cross-tenant stays unavailable |
| **LOADING / ERROR / SUCCESS** | Existing loading live regions; form alerts; success redirect | Harden associations; optional success copy under P3 |
