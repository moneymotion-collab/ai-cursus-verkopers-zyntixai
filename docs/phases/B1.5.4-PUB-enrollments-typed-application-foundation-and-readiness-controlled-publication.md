## 5. Authoritative Schema Summary

Foundation aligns with published Enrollment schema evidence:

- Table `enrollments` with org-scoped FKs to customer and program.
- Statuses constrained to the five known lifecycle values.
- Soft-archive via `archived_at` (terminal statuses only for archive/restore at DB).
- Open-participation uniqueness for non-archived pending/active/paused pairs.
- Authenticated INSERT/DELETE revoked; mutation via RPCs.
- Authenticated UPDATE grant limited to `owner_member_id` and `metadata`.
- Related `enrollment_status_history` for transition audit.

Database/RPC authorization remains authoritative over application helpers.

---

## 6. Enrollment Field Model

Core typed fields used by the foundation include:

- identity / tenancy: `id`, `organization_id`
- relationships: `customer_id`, `program_id`, `owner_member_id`, `created_by_member_id`
- lifecycle: `status`, `enrolled_at`, `started_at`, `completed_at`, `cancelled_at`, `archived_at`
- provenance: `source` (create path uses `manual`)
- extension: `metadata`
- timestamps: `created_at`, `updated_at`

Read models map these into typed list/detail shapes with Customer and Program display labels where loaded.

---

## 7. Lifecycle Matrix

Statuses: `pending`, `active`, `paused`, `completed`, `cancelled`.

| From | Allowed targets |
| --- | --- |
| `pending` | `active`, `cancelled` |
| `active` | `paused`, `completed`, `cancelled` |
| `paused` | `active`, `completed`, `cancelled` |
| `completed` | none |
| `cancelled` | none |

Application helpers mirror this matrix; database RPCs remain authoritative for enforcement.
