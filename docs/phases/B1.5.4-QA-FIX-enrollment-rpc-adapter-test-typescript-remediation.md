## 5. Exact Original Diagnostics

From B1.5.4-QA typecheck failure (line numbers as reported then):

1. `tests/server/enrollment-rpc-adapters.test.ts(247,7): error TS2741: Property 'reason' is missing in type '{ organizationId: string; enrollmentId: string; toStatus: "active"; }' but required in type '{ reason: string | null; ...; toStatus: "pending" | "active" | "completed" | "paused" | "cancelled"; }'.`
2. `tests/server/enrollment-rpc-adapters.test.ts(281,9): error TS2322: Type '"teleported"' is not assignable to type '"pending" | "active" | "completed" | "paused" | "cancelled"'.`
3. `tests/server/enrollment-rpc-adapters.test.ts(447,7): error TS2741: Property 'reason' is missing in type '{ organizationId: string; enrollmentId: string; toStatus: "active"; }' but required in type '{ reason: string | null; ... }'.`

All three belonged only to `tests/server/enrollment-rpc-adapters.test.ts` — scope matched.

---

## 6. Root-Cause Analysis

| # | Root cause |
| --- | --- |
| 1 & 3 | `TransitionEnrollmentStatusInput` is inferred from Zod with `reason: optionalTrimmedString(500)`, which after `.optional().nullable().transform(...)` yields a **required** `reason: string \| null` field on the output type. Typed adapter inputs that omitted `reason` failed `TS2741`. |
| 2 | Adapter parameter `input` is typed as `TransitionEnrollmentStatusInput`, so `toStatus` must be the Enrollment status union. Passing literal `"teleported"` directly into that typed position failed `TS2322`. The value is intentionally invalid and must enter through an untrusted/`unknown` validation boundary, not by widening the status union. |

Product types and schemas were correct; tests needed alignment.

---

## 7. Missing-`reason` Correction

For every typed transition input that omitted `reason`, added:

```text
reason: "Controlled enrollment transition test"
```

Targets preserved (`toStatus: "active"`). Behavioral purpose preserved (membership fail-closed; unsupported-RPC name scan). `reason` was **not** made optional in product schemas/types.

---

## 8. Invalid-Status Test Correction

`"teleported"` remains in the suite. It now enters as:

```ts
const rawUnsupportedTransition: unknown = {
  organizationId: ORG_ID,
  enrollmentId: ENROLLMENT_ID,
  toStatus: "teleported",
  reason: "Controlled enrollment transition test",
};
expect(validateTransitionEnrollmentStatusInput(rawUnsupportedTransition).success).toBe(false);
```

This is the same Zod schema `callTransitionEnrollmentStatusRpc` invokes. Rejection is still asserted. Malformed create/archive UUID adapter paths continue to prove no RPC is called. Removed the interim `as never` cast.
