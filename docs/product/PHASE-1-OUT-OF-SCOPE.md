# ZyntixAI Phase 1 Out-of-Scope Register

## 1. Scope Principle

Out-of-scope does **not** mean rejected forever.

It means the capability is **not required** for Phase 1 launch of the Course Sellers product.

Future phases may revisit deferred items through the Scope Decision Register.

## 3. Anti-Scope-Creep Rules

A feature must **not** enter Phase 1 scope because:

- it is "nice to have"
- Cursor can build it quickly
- a competitor has it
- it fits a future ZyntixAI vision
- it sounds impressive in a demo

A feature may enter scope only when:

- it maps to an authoritative problem (`P1-01`–`P1-15`)
- it supports a required workflow (`WF1`–`WF10`)
- it is recorded and approved in the Scope Decision Register

Future vision is not Phase 1 commitment.

---

## 4. Deferred-Idea Handling

Every new idea defaults to:

**`DEFERRED — REVIEW AFTER PHASE 1`**

unless formally approved through change control.

Proposed additions must be recorded in `PHASE-1-SCOPE-DECISION-REGISTER.md` before implementation planning begins.
